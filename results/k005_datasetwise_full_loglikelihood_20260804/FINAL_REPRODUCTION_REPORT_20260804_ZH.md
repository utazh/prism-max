# ContiguousKV / IMPRESS / Ours 独立数据集复现实验最终报告

日期：2026-08-04

## 1. 结论

1. 四个数据集、四个 KV 预算、三种方法的主矩阵已全部完成，共 48 组正式实验。严格 held-out 样本数分别为 SST-2 867、SubJ 998、TREC 495、RTE 272；每个数据集独立运行和统计，不做 410 条或跨任务请求池化。
2. Ours 相对 ContiguousKV 的系统收益稳定：16/16 个数据集-预算点的平均 TTFT 都更低，配对 bootstrap 95% 区间均完全小于 0；9814/10528 个请求更快。16 点未加权平均的平均 TTFT 和 P95 降幅分别为 24.76% 和 24.94%。
3. Ours 的准确率不是全面支配：相对 ContiguousKV 有 7 个显著提升点、1 个显著下降点、8 个无显著差异点。唯一显著下降是 TREC 10%（-10.91 pp，p=8.07e-9）。
4. TREC 10% 的 Uniform 单变量诊断表明，这个下降不是离线层敏感度表造成的：Uniform 44.24%，Sensitivity 44.04%，McNemar p=1.0。更可能的问题是 10% 档位下 P8 head0 在线重要性选择与恢复集合的交互。
5. ContiguousKV 的速度趋势复现较好：5% 下相对 IMPRESS 的四任务平均加速为 3.73x，接近原文 3.85x；25% 下为 3.19x，符合原文“预算提高后加速比下降”的趋势。
6. ContiguousKV 的准确率趋势没有复现：原文报告其相对 IMPRESS 在 5/10/25/50% 上平均提高 7.69/4.81/3.58/1.63 pp；本轮对应为 -2.23/-5.14/-11.28/-9.07 pp。完整候选 log-likelihood 修正了评测协议，但没有消除这一差异。

## 2. 实验协议

| 项目 | 设置 |
|---|---|
| 模型 | Qwen2.5-7B-Instruct |
| 执行 | 单请求并发度 1，数据集内请求顺序执行 |
| 计算 / KV 存储 | BF16 计算，FP16 Pcache |
| GPU | 服务器 GPU3 |
| GPU / CPU cache | 55 / 131 MiB |
| 存储 | 服务器 SSD，FlexGen/Pcache 路径 |
| warm-up | 每任务前 32 条 |
| 准确率 | 完整标签 continuation 的平均 token log-probability |
| TTFT | 标签补评分发生在 TTFT 截止点之后，不计入 TTFT |
| 预算 | 目标 5%、10%、25%、50%；同时报告 observed KV |
| Ours | HyperInfer 在线重要性、16-token 块、P8 选择复用、离线逐层预算、value-order 0.9、周期内已知选择异步预取 |

论文表 1 的 100/110/120/80 是 SST-2/SubJ/TREC/RTE 共享前缀中的 few-shot 示例数量，不是评测请求数。论文没有公开统一的 eval 请求数。

数据来源：SST-2 与 RTE 使用 GLUE 官方 split；TREC 使用官方 `train_5500/TREC_10`；SubJ 使用 Cornell 官方原始语料的固定 90/10 划分。SubJ 没有作者公开的 exact split。IMPRESS 重排历史 UID 32-35 在 bundle 构建时排除；每任务 1 条层预算校准 UID 在严格统计中排除。

最强的同预算结果：

- SubJ 25%：Ours 比 ContiguousKV 高 32.97 pp，平均 TTFT 快 13.46%，P95 快 16.27%；相对 IMPRESS 精度无显著差异（+0.30 pp，p=0.866），平均 TTFT 快 73.27%。
- TREC 50%：Ours 比 ContiguousKV 高 11.11 pp，平均 TTFT 快 24.53%，P95 快 32.17%；相对 IMPRESS 精度无显著差异（-1.21 pp，p=0.405），平均 TTFT 快 66.89%。
- RTE 25%：Ours 与 ContiguousKV/IMPRESS 的精度均无显著差异，平均 TTFT 分别快 32.47%/82.97%。

相对 IMPRESS，Ours 在 11/16 个点上准确率无显著差异，1 个点显著更高，4 个点显著更低；所有点均明显更快。因此稳定主张是系统加速，不能写成“所有任务准确率最高”。

## 4. observed KV 预算

四任务未加权平均 observed KV：

| 目标预算 | IMPRESS | ContiguousKV | Ours |
|---:|---:|---:|---:|
| 5% | 5.74% | 4.96% | 4.92% |
| 10% | 13.27% | 9.95% | 9.91% |
| 25% | 29.28% | 24.98% | 24.91% |
| 50% | 54.89% | 50.02% | 49.95% |

IMPRESS 使用 64-token 块，取整后经常超过目标预算；Ours 与 ContiguousKV 的 16-token 块基本对齐目标。因此与 IMPRESS 的精度对比不是完全相同的实际 KV 数，正式表必须保留 observed KV 列。

## 5. 预取机制证据

TREC 50% 同预算下：

| 指标 | ContiguousKV | Ours |
|---|---:|---:|
| Mean TTFT | 1190.9 ms | 898.8 ms |
| P95 TTFT | 1726.8 ms | 1171.3 ms |
| 关键同步 SSD 读取 | 14.0 MB | 1.46 MB |
| 总 SSD 读取 | 34.2 MB | 6.52 MB |
| 读取放大 | 1.244 | 1.023 |
| 平均预取等待 | 631 ms | 351 ms |

RTE 50% 同样表现为关键同步 SSD 读取 35.7 MB -> 9.91 MB、总读取 60.3 MB -> 16.1 MB、读取放大 1.215 -> 1.019、预取等待 1297 ms -> 758 ms。该结果证明速度提升来自减少无效读取并把 SSD I/O 移出关键路径，而不是少恢复 KV。

周期边界层 8/16/24 仍可能先使用上一层预测再补取，因此应称为“周期内部已知选择预取”，不能宣称全部层 100% 精确预取覆盖。

## 6. TREC 10% 失败诊断

| 方法 | Accuracy | Mean TTFT | P95 | Observed KV | Selector calls |
|---|---:|---:|---:|---:|---:|
| Sensitivity | 44.04% | 266.45 ms | 291.29 ms | 9.93% | 4 |
| Uniform | 44.24% | 265.27 ms | 309.01 ms | 9.93% | 4 |
| ContiguousKV | 54.95% | 454.61 ms | 514.61 ms | 9.96% | 4 |
| IMPRESS | 47.07% | 1270.93 ms | 1607.89 ms | 13.21% | 28 |

Uniform 对 Sensitivity 为 13 条错转对、12 条对转错，McNemar p=1.0。NUM 类只由 16/113 提升至 21/113，而 ContiguousKV 为 68/113。因此：

- 当前层敏感度表在 TREC 10% 几乎没有贡献。
- 层敏感度表不是该点准确率崩落的主因。
- 后续最小诊断应固定 Uniform 后比较 P8 与 P1，或比较 head0 与多 KV head；这属于下一轮，不应在看过 eval 标签后回填主结果。

本轮不能仅凭 SubJ 的强结果把准确率增益全部归因于层敏感度。若要把层敏感度写成独立贡献，需要使用训练 split 的独立校准集为每个预算重新生成层表，冻结后再做完整 Uniform/Sensitivity 消融。

## 7. 与原文图 9-11 对照

原文图 9：四数据集、三模型、5/10/25/50% 预算的准确率。原文称 ContiguousKV 相对 IMPRESS 平均提高 7.69/4.81/3.58/1.63 pp；本轮 Qwen2.5-7B 对应为 -2.23/-5.14/-11.28/-9.07 pp，方向不一致。因此 ContiguousKV 的准确率复现未成功。

原文图 10：四数据集、5% 与 25% 的平均 TTFT。原文 5% 下 ContiguousKV 相对 IMPRESS 为 3.85x，本轮为 3.73x；本轮 25% 为 3.19x，低于 5%，趋势一致。

原文图 11：SST-2/RTE、5% 的 P95。原文报告相对现有系统在不同模型上平均减少 0.42/0.89/1.17 秒。本轮相对 IMPRESS：ContiguousKV 在 SST-2/RTE 分别减少 0.781/1.421 秒，Ours 分别减少 0.825/1.462 秒。方向和数量级一致，但模型、硬件和图中汇总维度不同，不能当作精确数值复刻。

## 8. 准确率协议审计

旧 128 条 ContiguousKV 5% 记录：旧“贪心生成最多 4 token + 字符串匹配”、合法标签首 token、完整候选平均 log-prob 的正确数分别为 81/128、89/128、81/128。

旧协议 47 条错误中，宽松规则能标记 43 条“格式回声”；但完整候选协议只把其中 9 条从错改对，同时另有 9 条从对改错。旧记录没有保存完整候选所需 logits，因此不能仅对文本 JSON 免费重打分；正式矩阵已重新前向计算。

这说明 Claude 的判断只部分正确：字符串协议确实有问题，但 43/47 并不能全部免费修正。剩余准确率差异更可能来自闭源 ContiguousKV 选择器近似、作者未公开的 exact few-shot 样本/模板、SubJ split，以及 Qwen chat/tokenization 差异。

## 9. 可用结论与限制

可以支持：

- Ours 在相同 observed KV 下对 ContiguousKV 提供跨 16 个点稳定的 TTFT/P95 改善。
- 若干关键点同时改善准确率和延迟，尤其是 SubJ 25/50% 与 TREC 25/50%。
- Ours 在多个点以与 IMPRESS 无显著差异的准确率获得 59%-85% 的平均 TTFT 降幅。
- P8 周期复用与已知周期预取有选择哈希不变和 I/O 计数两类机制证据。

不能支持：

- ContiguousKV 准确率已经按原文完全复现。
- Ours 在所有任务和预算上准确率最高。
- 当前层敏感度已经被完整消融证明为独立贡献。
- 单请求结果自动外推到多请求吞吐或排队尾延迟。
